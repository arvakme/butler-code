# Dogfood

把产品当作用户实际使用，证明约定的用户流程在当前运行版本上是否成立。由默认开发交付流程 `delivery-verify` 按受影响行为调用，也可由用户明确要求；普通聊天、仅看代码的 review 和例行测试不单独启动。

沿用当前会话的项目规则、工具选择和授权。仅用户明确要求时派发：外部 CLI 经 herdr（`herdr-team` skill）派发，其余 agent 经 Agora，原生 subagent 仅按用户明确选择使用；否则当前 Agent 完成。该技能不依赖目录之外的指令文件。

## 定范围，再操作

- 有 PR、分支、diff 或验收合同：默认只覆盖受影响的用户路径及直接相邻的失败恢复路径。保留 PR 身份和真实 base/head；包含工作区改动时记录它们，不能把 HEAD 当成完整运行版本。
- 只有 URL、应用或命令：沿用户指定目标选核心流程；没有指定则先说明一个有限的探索范围。只有明确要求才做全应用探索。不要为凑范围切换用户检出或覆盖现有服务。
- 写清入口、环境、用户角色、预期结果和验收对象的版本。远程部署版本未知就注明未知，不把本地测试结论移植过去。
- 从真实任务列出场景，如创建后刷新、失败后重试、空状态进入正常状态。优先覆盖此次改动的行为，不机械套用每种边界；不设发现 bug 的数量指标。

## 按产品选工具

| 对象 | 实际操作 | 不能据此宣称通过 |
|---|---|---|
| Web | 默认 `ego-browser`，走真实用户路径 | 只读源码、HTTP 200、截图好看 |
| CLI / API | 真实入口、输入输出、退出码及可观察副作用 | 只有 mock 或单元测试 |
| 桌面 / 终端交互 | `cua-driver` 在后台操作目标窗口并回读结果 | 用底层命令调用代替物理手势 |

由当前 agent 直接驱动工具：Web 默认读取 `ego-browser` skill；原生界面或 Ego 的具体能力缺口读取 `cua-driver` skill。Cua 只做目标窗口的后台操作；需要前台、权限或用户接管时记为 `Blocked`，不能换工具绕过，也不能自动抢焦点。GUI 工具不可用时继续独立的 CLI/API 场景，不把间接证据补成通过。不因上游示例安装第二套浏览器。

沿用已有测试账号、隔离环境及授权。真实付款、对外发送、删除真实数据等未授权动作停在执行前，继续无关场景；测试授权不自动包含发布、提交工单或推送代码。

## 边执行边留证

开始操作前选定报告目录：优先现有工单或项目指定的验收产物目录；没有约定时用项目根的 `.delivery/dogfood-<唯一运行ID>/`。这是本次验收产物，不自动新增错题记录或进入 Git。在 delivery-verify 中直接使用该轮 result.json 和证据目录，不重复建立 Markdown 报告。独立调用时先创建报告，再逐场景更新；可从 [报告模板](assets/report-template.md) 裁剪，短任务也要保留范围、场景状态、证据和未测项。

- 跨页面、多步交互或动态反馈的录像按 [交互录像](../delivery-verify/references/recording.md) 复用 Ego 和现有 ffmpeg，带真实轨迹、点击圈与字幕；结果断言和视频分开记录。
- 保存动作、预期、实际结果与证据路径。确定性结果使用退出码、接口值或状态断言；交互问题保留必要的前后截图或录像。截图不能独自证明持久化或后端副作用。
- 发现问题后在允许范围内重试以确认；偶发或无法再次复现也保留原观察，标明次数、条件和不确定性，不升级为稳定复现或丢弃真实失败。
- 每个问题给稳定 ID、触发步骤、预期/实际、影响和证据。严重程度按用户影响判断，不按视觉醒目程度判断。
- 报告只放必要证据，不写 cookie、token、auth-state 或无关会话内容；登录状态由原工具管理，不能混进可分享的产物目录。产物发布与上传沿用当前授权。
- 用户中途问进度先回答，再继续验收。中断或工具失效时保存现场，不凭计划补写完成项。

## 状态与修复

独立报告的场景状态为 `Pending`、`Pass`、`Fail`、`Fixed`、`Blocked` 或 `Skipped`；在 delivery-verify 中沿用其数据状态：Fixed 只有实际重测通过才记 passed，不新增一套状态。`Fixed` 必须在修复版本重走原路径通过；`Skipped` 要有范围理由，不能用来隐藏失败或绕过必验项。

用户只要求试用时交付发现；已授权修复时处理范围内问题。修复后重跑失败路径及相关回归，记录前后版本和结果；需要产品取舍的事项单列决定，不为通过验收擅改需求。不要自动提交、推送、建 issue、上线或写错题本。

代码审查、自动测试和实际用户路径分别记录；已有相同版本的有效测试证据可复用，不为形成报告重复跑全套。必验项有失败、阻塞、未执行、无有效证据，或相关自动检查失败时，整体不能标为可交付。零 bug 也只有在声明范围已覆盖时才有意义。

结束时给出范围内结论、覆盖场景、问题及未测项、报告路径；只清理本轮创建的测试数据、服务和工具会话，保留报告与必要证据。不能清空用户浏览器或关闭既有 agent pane。

## 可选语义评估

默认由执行者结合验收标准判断；确定性事实直接检查。只有本次任务需要语义评分且已有模型调用授权时，才读 [Jev 评估边界](references/jev.md)。没有 Jev 不阻塞 dogfood；它的评分不能代替真实操作或自动批准发布。

本 skill 独立编写，参考 [Vercel 的复现证据流程](https://github.com/vercel-labs/agent-browser/blob/main/skill-data/dogfood/SKILL.md) 和 [Every 的按改动范围验收](https://github.com/EveryInc/compound-engineering-plugin/blob/main/skills/ce-dogfood/SKILL.md)。这里保留已有工具选择、herdr 调度及项目产物规则，不继承它们的工具独占或自动提交行为。

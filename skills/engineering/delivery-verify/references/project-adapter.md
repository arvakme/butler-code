# 项目验收适配层（`.agents/acceptance/`）

delivery-verify 不猜项目怎么跑。启动、端口、账号、界面入口写在项目自己的 `.agents/acceptance/PROJECT.md` 里：怎么跑听项目的，什么算有效验收听本 skill 的。没有这个目录时，本次验收用到的步骤就是它的初稿——跑通后写进去再交付。

```text
<repo>/.agents/acceptance/
├── PROJECT.md            # 适配层，固定六节，提交
├── common-mistakes.md    # 本项目被打回过的问题，提交，只追加
└── scripts/              # 可选：启动、造数据、探针脚本
```

报告和证据不进仓库：放在项目根的隐藏目录 `.delivery/<任务>/`，并写进 `.git/info/exclude`。

## PROJECT.md 固定六节

节号固定，别处按 `PROJECT.md §2` 引用。

```markdown
# PROJECT.md — <项目名> 验收适配

## 1. 项目概要
一段话说明产品是什么；测试相关的目录：服务端、前端、桌面壳、CLI 各在哪。

## 2. 环境
- 启动：`<命令>`（地址 `<url>`，端口 `<port>`，版本来自 `mise.toml`）
- 停止：`<命令>`（只停本次启动的进程）
- 判断已在运行：`<命令>`，已在运行就复用，不重启用户的服务
- 依赖服务：<数据库 / 队列 / 对象存储> 及各自启动方式
- 冒烟：`<一条最短的端到端命令或 URL>`
- 上线后（有线上服务的项目）：生产冒烟 `<命令>`，生产回读 `<命令>`。回读检查数据是否仍在更新（最近一次成功同步、刷新、写入的时间），不只是页面返回 200；写明各数据源的过期阈值。

## 3. 账号与登录
测试账号、造数据命令；每个界面一条"是否已登录"的检查。登录靠注入（cookie、token 文件、环境变量），不做交互式登录，不动用户日常浏览器。

## 4. 界面入口
适用的 CLI / Web / 桌面 / iOS 模拟器，各写启动方式、入口地址、Ego 空间名或窗口标识。

## 5. 快速到达状态
直达常用页面或状态的办法：路由、URL 参数、种子数据、调试开关、错误注入点。

## 6. 已知约束
只在 macOS 可用的部分、必须先起的服务、需要单独安装的子包、会误伤的操作。
```

## 维护

- 验收中发现 `PROJECT.md` 与实际不符，当场改正并在 `process` 里记一行；不要绕过它另写一套命令。
- 用户打回某项时，把原因写成一条可检查的规则追加到 `common-mistakes.md`（格式见 [common-mistakes.md](common-mistakes.md)），下一轮交付前先逐条对照。

结构参考 lobehub/lobehub 的 acceptance skill（Apache-2.0），按本机工具链改写。

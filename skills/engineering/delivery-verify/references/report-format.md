# 离线报告数据

复制 [示例](../assets/result.example.json) 到独立轮次目录，编辑 result.json，然后运行：

```bash
python3 ~/.config/butler-code/skills/engineering/delivery-verify/scripts/report.py /absolute/round-01/result.json
```

只需 Python，无需 node、服务或网络：脚本把本轮数据填进预先构建好的模板 `assets/app/index.html`。输出为同目录 report.html（约 1.7MB，全部内联，含字体），媒体保留相对引用，文字证据与检查日志内嵌（每份最多 64KB，超出标注截断）；生成后按 [分享参考](sharing.md) 注册整个轮次目录并给出 Tailscale HTTPS 地址；带历史链接则注册整个任务目录。报告生成后不覆盖；返工建立下一轮。`--check` 只校验数据及引用，不写文件。命令退出 0 是生成/校验成功，不是业务通过。

产物只留本地一周：`scripts/prune.py` 删除最新文件已超过 7 天的整个任务目录（含空目录），范围是项目里的 `.delivery/` 和 `.artifacts/`，只动这两处；默认演练，`--apply` 才删。需要长期保留的证据放进项目仓库或别处。

界面用 React + `@lobehub/ui`（MIT）对照 LobeHub 开源的 Acceptance Viewer 重建：顶部身份带是标题、结论胶囊、待你验收、摘要、运行版本与本轮依据的反馈；四个标签页——验收项、过程、文件、讨论。讨论是时间线：每一轮 Agent 的交付、你每次提交的决定（接受、要求修改、原因、图上和视频里的意见、投递状态），下面是总体意见框。验收项是一张带分隔线的列表，默认全部展开，展开收起有高度动画；筛选下拉带计数（未通过→需修复，已通过→已通过，其余→未完成）；截图按自己的比例显示（窄长的手机图不再被拉成整栏宽，最高约六成屏），点开是居中的大图对话框，不占满窗口：可缩放、←→ 切图、Esc 关闭，并可在图上框选一个区域或点一个点写意见；录像同样按比例限高，带逐帧前后（`,` `.`）、倍速，暂停在某一刻点“在 0:02.0 写意见”，时间轴上留标记；这些意见带位置存入本轮并自动算作打回该项，提交后在反馈文本里写成“图 xx.png 区域 左31% 上20% 宽38% 高9%”或“视频 xx.mp4 1:04.1”，完整坐标在回执 `rejected[].notes`；文字证据是可展开的文件卡片；每项可“接受”或“要求修改”（要求修改时可多选原因标签：布局、颜色、文案、功能不对、没做到、证据不够，写原话，并可选“存成教训”，下面预览会记下什么），底部悬浮决策栏显示接受与要求修改的数量，可提交决定或全部接受，按钮直接交回绑定的 Agent 会话；筛选有三个下拉：你的决定（待你决定、已接受、要求修改）、轮次、Agent 的结果；只有拿到本次提交编号与持久 user turn 确认才显示成功。标签页、筛选、展开项写在地址 # 里，复制地址能打开同一视图；打回与意见按任务和轮次暂存在浏览器本地。视觉沿用 Arvak 博客（`~/Devs/arvak-blog-purple`）的紫色设计语言：brand 紫与浅紫、紫色渐变主按钮（悬停流光）、流光下划线、页面边缘的淡紫光晕与像素抖动纹理、闪烁星点，全部接受时飞出一簇星点；交互图标用 Dither Icons（MIT），悬停、聚焦或点击时播放各自的动作；字体 Geist / Geist Mono 内嵌。深色是博客的紫黑底，跟随系统。关闭了组件库的在线字体与 CDN，静态报告无外部素材请求；反馈仅请求同源回传入口。减少动态效果时所有动画停止。窄屏无横向滚动；减少动态效果偏好会关闭动画。

改界面：源码在 `ui/`（`mise.toml` 固定 node 24，pnpm）。`cd ui && pnpm install && pnpm build` 重新生成 `assets/app/index.html` 并一起提交；`python3 scripts/report.py <result.json> --model ui/dev/sample/model.json` 生成样例后 `pnpm dev` 可本地预览。旧轮报告不重新生成，新轮使用当前模板。

反馈通过同源 HTTPS 入口直接提交，不使用剪贴板。按钮发送本轮 task、round、完整意见、打回项和稳定提交 ID；交付看板持久保存反馈后，经 `herdr agent prompt` 向登记的 herdr pane 发一行指向回执文件的消息。重复编号不会再派发，未确认或网络失败时保留意见并明确显示状态。见 [分享参考](sharing.md)。

## 多轮：历史、已关闭的项、对比

从交付看板的地址打开时，页面会读同目录的 `history.json`（看板即时汇总各轮 result.json 和已保存的回执，不另存一份）：每个验收项显示“轮次历史”（每一轮的状态、你的决定和原因），上一轮已接受且没被重开的项在下一轮自动折叠并标“第 N 轮已接受”，并可把上一轮的同名图（没有同名就按顺序）与本轮拖动对比。所以返工的新一轮里，同一张图沿用同一个文件名，历史对比才找得到。离线打开没有这些，只显示提示。

## 用户流程（可选）

验收项是同一条用户路径上的几步时，在 result.json 顶层写 `flows`：每个流程有 `id`、`title` 和按顺序的 `steps`，每步指向本轮的一个验收项 `case`，`label` 写“用户做了什么才从上一步走到这一步”（第一步不写）。例：`{"id":"recover","title":"从银行卡被拒绝中恢复","steps":[{"case":"see-reason"},{"case":"keep-cart","label":"回到结账页检查购物车"},{"case":"retry","label":"换一张卡点“重试”"}]}`。页面多出“用户流程”页签，是一块可以拖动的画布：每个流程是一行卡片，卡片之间用带箭头的线和 label 连起来，卡片显示你的决定（接受、要求修改、忽略）或 Agent 的结果、说明、走过的轮数和证据数量，点卡片跳到那个验收项；没有归入任何流程的验收项排在最后一行。拖背景平移，拖卡片调整位置（记在本机浏览器，“整理”一键放回），⌘ 或 Ctrl 加滚轮或按钮缩放，手机上双指缩放，“适应”框住全部，右下角有缩略图，可全屏；顶上的标签可以只看一个流程，从看板地址打开时能按轮次回看各轮的流程。不写 `flows` 就没有这个页签。

## 每轮的说明与表情

可选的 `message`（Markdown，最多 8000 字）是 Agent 这一轮写给用户的话：这一轮改了什么、请重点看哪里。支持段落、标题、列表、引用、代码块、粗体、斜体和 http(s) 链接，不执行任何 HTML。它显示在讨论页签里这一轮的交付卡片上，不写就显示 `summary`。用户可以在每轮的卡片和自己提交的决定上点表情（👍 ❤️ 🎉 👀 🤔 ❓），记在这一轮目录的 `reactions.json` 里，只有 `history.json` 和这个文件看得到，不会往 Agent 的会话里发消息；下一轮开工前读一眼。

## 接受、要求修改、忽略

每个验收项用户有三个选择：接受、要求修改、忽略。忽略表示这一项不用处理（不需要、不适用、以后再说）：下一轮不要为它返工，也不要把它当作被拒绝；和接受一样，下一轮默认折叠并标“第 N 轮已忽略”。回执里 `ignored` 是这些项的 ID。

## 证据的呈现

- 文件页是错落的卡片网格：截图显示缩略图（立即加载，失败重试一次，再失败显示图标卡片），录像是图标卡片，文本显示前几行；每张卡片有文件名、完整描述、所属验收项和阶段，点卡片在新标签页打开原文件，可按截图、录像、记录筛选。

- 同一状态的两张图（浅色和深色、改前和改后）：给两条证据设相同的 `group`，各自写 `label`（如“浅色”“深色”），相邻放置；页面并排显示，也可切到滑动对比。`label` 必须配 `group`。
- 文本证据：`.json`（对象数组、值数组、或一层对象）和 `.csv` 直接画成表格（最多 200 行、12 列，被截断的不画）；`.log`、`.txt` 是深色等宽块，默认折到 6 行，可展开、可复制；`.md` 和其余 JSON 仍是可展开的文件卡片。

## 字段

示例中的字段均必填。字符串必须非空；cases 至少一项。process 是已经发生的步骤，按顺序写，不把计划当完成。revision 写 commit 加工作区差异及运行对象；created_at 使用带时区 ISO 时间。review 如实区分自审、未审阅和带回执路径的独立审查。limitations 可以为空数组，但不可用它掩盖必验项状态。

每项 case 有稳定 id、title、required、method、expected、status、observation、evidence_required 和 evidence。status 只能是 passed、failed、uncertain、blocked、pending、skipped。skipped 的 observation 必须说明原因；修复后真实重测通过才改 passed。required 在执行前确定。

证据结构：

```json
{
  "kind": "image",
  "path": "evidence/after.png",
  "caption": "提交后重新打开仍能看到保存结果",
  "source": "2026-09-21T10:05:00+08:00 · Ego · commit abc + 本轮 diff；原始采集",
  "phase": "final",
  "inspected": true
}
```

kind 是 image、video 或 text；图片支持 PNG/JPEG/WebP/GIF，视频 MP4/WebM，文本 TXT/LOG/JSON/MD/CSV。可选 `group` 与 `label` 见上。phase 为 process 或 final。source 写实际采集时间、运行版本、工具；复用时保留这些信息并注明原因。inspected 表示执行者已查看，不是生成器自动判断内容真实。path 必须是轮次目录内存在、非空的相对文件，不能是 URL 或逃逸的符号链接。媒体是静态证据，不嵌入其他可执行 HTML。

passed 至少有一份已查看证据，且 evidence_required 指定的类型全部存在；UI 默认包含 image，动态行为需要 video。生成器不能鉴别伪造截图或代替执行者判断；它只阻止缺证据的通过声明。

checks 数组独立记录实际自动门；每条有 name、command、exit_code（原始整数，未执行为 null）、log（轮次内非空文本文件）。不要记录 `命令 | grep/head/tail` 的退出码冒充测试本身。失败门未解决就保留失败，新轮记录重跑结果。需要表达不适用时在 process 或 limitations 解释，而不是填一条假成功命令。

cleanup.complete 仅在本轮所有自建资源已关闭并验证，或明确有意保留时为 true；notes 给出精确句柄及关闭证据/保留理由。无新建资源也如实写明。详细资源记录可作为 text 证据，不放密码或 token。

可选 feedback 是本轮收到的用户反馈；previous_report 是同一任务内上一轮 report.html 的相对路径，例如 `../round-01/report.html`，必须存在。不接受 URL。

## 总状态

- 任一验收项 failed 或任一检查非零退出：未通过。
- 其余情况下，必验项不是 passed、检查未执行或清理未确认：验证未完成。
- 至少一个必验项，且以上条件全满足：范围内验证通过。

所有状态都单独显示“待你验收”；报告不写入用户已接受，也不自动触发发布。数据校验失败返回非零并拒绝写报告，不能静默丢失附件或把失败降级成通过。

## 说人话摘要

`summary` 是用户最先读的一段，写成大白话，不超过三句：做了什么、能不能用、哪里没测。不用没解释过的行话（「银弹」、幂等、竞态……要么换成日常说法，要么第一次出现时用一句话讲明白）。证据、检查日志和细节放在下面的验收项里，不堆进摘要。

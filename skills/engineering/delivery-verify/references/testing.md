# 测试：价值门、先红后锁

写、改或清理测试时读。测试是负债：每条持久测试都必须在失败时说明某个真实行为坏了。覆盖率、测试数量、“每个函数一条”都不是目标。测试结果只进 `checks`，不替代验收项。

## 价值门

写新测试和保留旧测试共用这道门，六条全部成立才留：

1. **有来源**：保护的行为有独立依据——用户要求、bug、公开合同、可访问性规则或规格示例。
2. **失败有意义**：一种可信的回归会让它失败，且失败对应调用方或用户可见的问题。
3. **期望值独立**：期望值来自已知字面值、规格或示例，不是按实现再算一遍。
4. **稳定接缝**：经公开接口或稳定边界观察，不依赖只为测试存在的导出、flag、wrapper 或注入点。
5. **抗重构**：行为不变的内部重构、无关文案或布局调整后仍然通过。
6. **唯一 owner**：同一合同只在最低的可靠边界证明一次，且没有被类型系统、编译器、lint 或已有测试等价保证。

复杂功能优先端到端证明，纯规则放领域测试，编排和授权放应用层；端到端只留关键用户流程。

**像实现但必须保留**：公开 API、协议与序列化字节、配置、迁移、存储格式、安全、默认值、跨语言生成物、架构约束——它们本身就是合同。

## 反模式

读完测试和被测代码再判，文本命中只是线索。

- **同义反复**：按实现的算法重算期望值；mock 返回什么就断言什么；期望值由被测函数自己产出。
- **变更探测器**：扫源码、import 或字符串；数导出、路由或清单行数；快照生成的 markup 或 class 串；断言私有协作者、调用次数或调用形状。
- **重复**：同一场景在它穿过的每一层都重放；近乎相同的用例（合并成表驱动）；类型已保证的检查。
- **空洞**：没有断言或只证明“没崩”；只测 getter、常量或框架能渲染。
- **虚假信号**：负向用例因无关原因通过（别的守卫先拒绝）；fixture 替被测方产出本该由它产生的结果；测试名承诺的比输入实际覆盖的多。
- **外观当行为**：尺寸、坐标、computed style、布局 class 是外观证据；用 role、可访问名定位控件，断言落在用户任务完成上。视觉效果用截图证据，不写进断言，除非项目明确采用视觉回归。

## 先红后锁

实现一项行为变更时，把能自动化的验收标准先写成行为测试：

1. **见红**：运行并保存失败输出，确认红的原因是“还没实现”，不是环境、拼写或导入错误。为已有行为补测试时，临时破坏被测实现（不是改断言）看它变红，再精确还原。从没红过的测试只证明了 mock。
2. **锁**：记录这些测试文件的指纹，存进本轮目录，例如 `shasum -a 256 <测试路径…> > <round>/test-lock.sha256`。改变既有行为时，先把旧断言改到新行为再锁，并在报告里写明删改了哪些断言。
3. **实现**：自由完成整个切片，内部测试同样过价值门。
4. **核锁**：交付前 `shasum -a 256 -c <round>/test-lock.sha256` 必须全部 OK。有不一致就是改了考卷：停下，在报告里说明原因，不自行放行。

例外：无行为变化的改动（重构、改名、搬移）以已有测试为准，跳过先红后锁；落不成自动测试的（视觉、交互手感）按验收项取截图或录像证据，并标注“未自动化”。修 bug 时只有已有行为测试留有真实缺口才加回归测试，且它必须先在原 bug 上失败。

## 接缝与红绿切片

> 本节并入自 mattpocock/skills@c55ee46 `skills/engineering/tdd`（MIT，许可见 `~/.config/butler-code/profiles/licenses/mattpocock-skills.txt`），取代已退役的 `tdd` skill。

- **接缝**是测试所在的公共边界：不深入内部就能观察行为的接口。测试放在接缝上，绝不针对内部实现；测试名和接口词汇沿用项目 `CONTEXT.md` 的领域语言，并遵守所改区域的 ADR。
- **先定接缝再写测试。** 优先沿用现有公共接口、测试位置和验收项，选最高层、跨越代码最少的接缝（理想是一个）。只有新接口涉及未定的产品行为或实质架构取舍时才向用户确认；常规测试和修复不需要额外许可。接口形态本身有疑问（模块多深、接缝放哪、暴露什么）时查 `codebase-design` 的词汇。
- **垂直切片，一次一个。** 每个循环是一个接缝、一个失败测试、一个刚好让它通过的最小实现，不预判后续测试、不加推测性功能。先写完所有测试再写实现（水平切片）会测到想象中的形状而不是用户可见行为。
- **只在系统边界 mock**：外部 API、时间与随机、有时是数据库或文件系统；不 mock 自己控制的模块和内部协作者。边界处用依赖注入，并把外部操作写成一个操作一个函数的 SDK 式接口，而不是一个通用 fetcher，这样每个 mock 只返回一种形状、测试设置里没有条件分支。
- **保持绿灯再整理。** 行为被测试保护后才做局部重构，并复跑受影响检查；独立的架构调整另行界定范围。

## 顺手清理

本次触及的测试文件及同一行为的相邻用例，按价值门逐条判：保留、重写或删除，写明删除理由。范围只限本次触及的部分；全仓审计只在用户明确要求时做。

# agents：后台能力

Pi 里我自己的后台能力：哨兵（sentinel）、调研（research）、未了事项（loose）、纠错本（lessons）、选择题（choose）、预测输入（predict）。各自由配置开关控制，互不依赖。没有斜杠命令：模型自己调用工具（`sentinel`、`research`、`loose`、`lesson`），用户用大白话说“盯着这个 PR / 这个文件夹 / 那台机器”“去调研”就会触发；界面上的操作在状态栏的任务弹窗里（按键或点击）。审查与子代理不在这里，用 FireCode 的 `review/` 与 `master/`。

不创建子会话或 Worker 池：每个功能都是一次性迷你 agent（`mini.ts`，用 Pi 自己的 agent 内核和模型注册表）。主会话注册全部功能；子会话（指挥官的子代理、审查者）只注入纠错本，不给工具。

- `config.ts`：解析 `<agent 目录>/extensions/butler-ui/config.jsonc` 的 `agents` 节（文件由根 `config.ts` 读），严格校验，写错的功能拒绝启动；没有这一节就全部关闭。模板是根目录 `config.example.jsonc` 的 `agents` 节。
- `lessons/`：`text.ts` 纠错本的解析和压缩（纯逻辑，`tests/lessons.test.ts`）；`index.ts` 在 `before_agent_start` 里把全局和当前项目的纠错本作为 `<lessons>` 段落放进系统提示，像技能的目录：每本纠错本取文件开头 YAML 头里的 `description` 作说明，再列每条规则的开头一行（`lessons.mode` 默认 `index`；`full` 是放得下就全文），细节需要时 agent 自己去读文件；太长就只留最新的，并提供 `lesson` 工具按格式记新的一条。只给 Pi 用：Claude Code 和 Codex 只是执行者，不需要。
- `loose/`：内置的“会话哨兵”（未了事项）：每个会话自动启动，输入框上方只有一个哨兵，平时不占行，有事才出现。`store.ts` 账本（每个会话一份，文件名是会话号，放 Pi 的 agent 目录 `loose-ends/`，不进仓库；新开的会话是干净的，恢复同一个会话时还在，会话结束时没有未了事项就删掉，超过 30 天没动的陈旧账本会被清掉，同一个目录里开几个会话互不串；去重、按编号或文字找、该提醒和该交给 notify 的判断，纯逻辑）、`text.ts` 扫描的提示词与解析（纯逻辑）、`scan.ts` 让便宜的模型翻对话、`index.ts` 工具 `loose`、系统提示、底栏登记、提醒。两路来源：我自己记；便宜的模型每隔几轮和压缩上下文之前翻对话找漏的，找到的先是候选，用户确认才算。弹窗里每一条（待确认的、没做完的、机器上的提醒）都能直接处理：每一条只有两个动作：`g` 去做（把它作为用户的指令交给 Pi，立刻开始，弹窗关掉；候选同时确认；提醒带着具体的做法，比如改了没提交就看改动并整理提交，两小时内不再提）和 `x` 忽略（待办和候选是划掉；提醒是一直忽略到那件事自己消失，存在账本的 `mutes` 里）。积压很多时（比如 32 条）不让用户一条条处理：`整理`（弹窗按 `t`）让便宜的模型对照最近的对话判断每一条还要不要做——能明确看出做完了、因为后来的进展已经过时、或重复的，直接划掉并留记录（`recent`，`loose` 工具的 `list` 能看到，`reopen` 撤销；不按放了多久判断，要看后来发生了什么，拿不准不动），其余给建议（去做 / 忽略 / 要你定），弹窗里按建议分组；扫描时发现过时的也一样处理。弹窗里空格给一条打勾、`a` 勾上整组，勾选后 `g` / `x` 对整批生效；`y` 照建议处理（忽略的划掉，去做的分批交出，要你定的不动）。分批接力：一次交出的事每 8 条（`BATCH`）为一批，作为一条结构化的用户消息发给主 Agent，这一轮结束（`agent_settled`）后清点做完几条，再发下一批；用户中途插话就暂停（弹窗按 `p` 继续或暂停、`s` 放弃）；底栏显示“第 k/n 批，已做完 d/total”；全部发完汇总一条通知（8 条以上也交给 notify）；没做成的留在清单里，不自动重发。进度存在账本的 `queue` 里，会话重开时停在半路的接力放回队首并暂停。积压超过一批时，每轮结束的提醒改成一句“积压了 N 件，先整理”，不再罗列。`signals.ts` 看机器上的客观状态（改了没提交、提交了没推送、验收报告在看板上等着用户），超过 2 小时才算，不靠对话。提醒：每轮结束一行、你离开很久回来或重开会话时汇总、放太久交给 notify 命令（同哨兵）。
- `sentinel/`：`watch.ts` 纯逻辑（快照与差异→事件）；`index.ts` 轮询、通知、失败日志用便宜模型解读、跨重载恢复。盯“任何东西”靠 `cmd`：一条快速只读的命令每隔一会儿看一眼，输出一变就通知；给了目标（goal）就让便宜的模型判断每次变化值不值得说、目标是否达成；`until`（正则或 exit0）是确定的结束条件。pr、ci、url 是内置的预设。
- `choose/`：选择题。每个回合结束先用规则筛（结尾像提问且带并列选项），过了才让小模型判断并整理成 2 到 4 个选项，用 `ctx.ui.select` 弹出；选了就当作用户消息发出，Esc 关掉，“自己写…”转成输入框。展示、选择、关掉记在 `choose-log.jsonl`，最近 10 次里关掉的比例过高就每三次才问一次。
- `predict/`：预测输入。装饰已有的输入框（状态栏的输入框外壳，没有就用 Pi 的），只在输入框为空且有建议时多画一段灰字、多接一个 Tab；其余按键原样交给 Pi。每次采用、展示、忽略记在 `predict-log.jsonl`，用来给下一次预测当示例，采用率太低就自动降低频率。
- `research/`：`native.ts` 一位调研员 = 一次带 `web_search_options` 的请求（模型用自己服务商自带的网页搜索，经支持该参数的 OpenAI 兼容网关）；`index.ts` 让配置里的几位各自独立查同一个问题，再合并并交叉验证，结果放在 `<Pi 目录>/research/`（只留最近 30 份）。

测试：纯逻辑在 `tests/`（`bun test` 会跑）；端到端在 `e2e/`：真实的 Pi（RPC 模式）、真实的模型（脚本里写的是维护者自己网关上的模型名，换成你有的），会产生真实的模型调用，不进 `bun test`。`sentinel.e2e.mjs`（会变化的 gh 替身 + 一次真实 gh）、`sentinel-any.e2e.mjs`（真实文件和进程，含模型按目标判断）、`loose.e2e.mjs`（记、去重、系统提示、模型自己记、提醒、扫描出候选并确认）、`loose-sessions.e2e.mjs`（同一目录两个会话互不串，空账本会话结束时删掉）、`loose-footer.e2e.mjs`（tmux 里底栏的数量和明细行）、`loose-backlog.e2e.mjs`（20 条积压：整理、批量忽略、分批接力）、`footer-jobs.e2e.mjs`、`footer-workers.e2e.mjs`（指挥官派的子代理在底栏和弹窗里）、`lessons.e2e.mjs`、`choose.e2e.mjs`、`predict.e2e.mjs`、`research.e2e.mjs`（真实搜索）；模型会不会自己选对工具由 `research-tool`、`sentinel-tool`、`sentinel-any-tool` 验证（大白话提问，检查它调用了对应工具而没有轮询或开 agent）。运行 `node agents/e2e/<名字>.e2e.mjs`。


`jobs.ts` 是任务登记簿（放在 `globalThis` 上）：哨兵、调研、未了事项，以及 FireCode 的审查和指挥官派的子代理（`firecode.ts` 镜像进来，真源仍在 `review/`、`master/`；审查释放占用时读终态 checkpoint，由 `review-report.ts` 生成 delivery-verify 报告并登记交付看板，同一个 runId 只出一份）开工时登记（角色、标题、完整任务、模型、并发成员、此刻在做什么、最近动态），结束时标明结局（完成 / 失败 / 已停止）和结果，但不删除——留最近 20 个已结束的，弹窗里变灰沉底。状态栏和任务弹窗（`Ctrl+\`）读它。进度只能拉取、不发变化事件的任务（审查、子代理）带 `now()`，绘制时现取。每位成员（调研员）还记着完整过程（`trace`，最多 400 行：`→ 工具 参数`、`← 工具 结果`、`说 …`、`想 …`、`· …`，由 `mini.ts` 的 `onTrace` 写入），弹窗里可以进入查看。模型一栏写请求的名字（Magpie 的模型组由 Magpie 路由）。
